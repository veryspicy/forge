# Forge 商品图防盗与溯源方案

> 目标：降低商品图片被盗用/店铺被克隆风险，并在图片被转载后能通过技术手段完成"图片归属 + 下载来源"取证。
> 状态：方案评审稿，待用户确认决策项后分批实施。

## 1. 现状盘点

| 环节 | 现状 | 文件 |
|---|---|---|
| 上传 | admin `POST /api/admin/v1/resources/upload` → `MinioService.upload_bytes()`，图片存 MinIO（不可达时降级本地 `/uploads/site/`） | `backend/src/forge/api/admin/v1/resources.py`、`backend/src/forge/infrastructure/services/minio_service.py` |
| 缩略图 | 上传流程已用 pillow 生成 `resources/thumbs/{uuid}.jpg` | `resources.py` `_derive_thumb_url` |
| 展示 | portal-web 页面引用 `/minio/**` 或 `/uploads/**` → `media-proxy.ts` 代理 → backend `minio_proxy.py` 从 MinIO 读出返回 | `portal-web/app/server/middleware/media-proxy.ts`、`backend/src/forge/api/minio_proxy.py` |
| 已有基础 | 资源表已存 `sha256`（精确指纹）；后端已依赖 `pillow>=13.0.0`；gateway 为 nginx 可做 referer 层 | `resources.py` `_serialize` |

**结论**：目前图片为公开 URL 直出，无任何防盗与溯源手段；但"上传即处理（pillow）"与"请求集中过 proxy"两条链路天然适合嵌入保护逻辑，改造点清晰。

## 2. 行业对标

| 防护手段 | 行业实践（Shopify 生态 / Cloudflare / 独立站） | 数据/要点 | 对 Forge 的适配 |
|---|---|---|---|
| 防盗链（Hotlink Protection） | Cloudflare/ImageKit 提供 referer 过滤，外域引用返回 403 | 可拦截约 91% 直接链接抓取 | gateway nginx 加 referer 校验，低成本高收益 |
| 签名 URL（Signed URL） | Cloudflare Images 官方方案：HMAC-SHA256 签名 + exp 过期时间，后端生成 token | 无 token 不可访问；密钥只在后端 | backend 生成/校验签名，proxy 链路集中，改造可控 |
| 可见水印 | Shopify 卖家主流：角落微水印、透明度 30-40%、面积 ≤5% | 面积 >15% 时加购率降 22%；≤5% 不影响 Google 图片索引 | 上传时 pillow 自动加角标水印，可选开关 |
| EXIF/元数据标记 | 导出时写入版权声明与唯一 ID | 仅元数据级，图片转发后易丢失 | 作为辅助（不可依赖） |
| 不可见数字水印（隐写） | Digimarc 等商业方案，DCT/LSB 嵌入 | 抗压缩/截图能力弱于指纹，但可指认下载者 | 下载/请求时动态嵌入会话 ID，配合日志对账 |
| 感知哈希指纹（pHash） | TinEye / Google Lens 反向图搜底层技术 | 缩放、裁剪、压缩后仍可相似匹配 | 建立商品图指纹库，定期扫网比对 |
| DMCA / 平台投诉 | 独立站标配：发现盗用后走 DMCA 下架 | SellerShield 数据：提交后 7-10 天下架率约 82% | 取证完备后作为法律兜底 |

## 3. 方案设计（分层防护）

### 3.1 第一层：访问控制（防盗链 + 签名 URL）

**目标**：阻止外站直接引用与无授权抓取。

1. **gateway nginx 防盗链（先行，零代码）**：
   - 对 `/minio/`、`/uploads/` 图片路径启用 referer 校验，空 referer 与同站域名放行，外域返回 403。
   - 注意：C 端与 admin 同源（统一走 8080 网关），referer 策略只拦外域直链。

2. **签名 URL（进阶，backend 实现）**：
   - 由 `minio_proxy.py` 统一校验签名：URL 携带 `exp` + `sig`（HMAC-SHA256(secret, path + exp)）。
   - 图片 URL 由后端生成时自动附带签名；未带或过期签名返回 403。
   - 密钥仅存 backend 环境变量，不入库、不进前端代码。
   - 缓存权衡：签名带固定长过期（如 7 天），CDN/浏览器缓存不受影响。

### 3.2 第二层：水印（威慑 + 品牌曝光）

**目标**：即使被下载，图上也带品牌标识，降低商用价值并反向曝光。

1. **上传自动加水印（admin 上传时）**：
   - 基于已有 pillow 链路，在上传主图/生成缩略图时叠加半透明角标水印。
   - 参数：角落位置、透明度 30-40%、面积 ≤5%（对齐行业数据，避免转化率与 SEO 损伤）。
   - 水印图片源：admin 站点设置可上传品牌 Logo（默认关，开启后全站商品图生效）。

2. **前端展示水印（可选，portal-web）**：
   - C 端商品图加载后叠加半透明品牌标识层，仅视觉存在、不写入图片文件——防"截图盗图"。

### 3.3 第三层：溯源取证（指纹 + 隐写）

**目标**：图片被转载后能证明"图是我们的 + 谁从我们站下载的"。

1. **感知哈希指纹库（pHash，主力）**：
   - 上传时对主图与缩略图计算 pHash（或 dHash），与现有 `sha256` 一并落库（`resource` 表加 `phash` 列）。
   - 取证流程：发现疑似盗图 → 计算其 pHash → 与库中商品图比对相似度 → 命中即证明图片归属。
   - 配套脚本：批量回填存量图片指纹（一次性迁移）。

2. **下载溯源隐写（辅助，追责到人）**：
   - 在**原图下载接口**（非页面展示）动态嵌入不可见水印：内容 = 会话 ID/用户 ID + 时间戳。
   - 同时记录"谁在何时下载了哪张图"到日志（access log 已有会话信息，补充用户字段）。
   - 取证闭环：被转载图 → 解出隐写 ID → 对账下载日志 → 定位盗图账号。
   - 注意局限：经过压缩/截图/二次处理的水印可能损坏，仅作辅助证据。

3. **版权存证（可选）**：
   - 上传时对原图计算 sha256 + 时间戳做可信时间戳/区块链存证，为 DMCA/诉讼提供时间证据。

4. **admin 取证入口（自助工具）**：
   - 资源管理页新增"取证验证"入口：上传疑似盗图 → 后端自动执行三步——①sha256 精确比对 + pHash 相似度比对（命中即证明归属，输出相似度得分与命中资源列表）；②隐写提取（解出会话 ID/用户 ID/时间戳，若 C 端全量隐写生效则可还原下载者）；③下载日志对账（按解出的会话 ID 反查下载记录，输出时间/IP/账号）。
   - 输出：取证报告（结构化 JSON + 可读摘要），可导出归档。
   - 依赖：P2 指纹库 + P4 隐写提取，随 P4 一并交付。

### 3.4 第四层：监测与维权（运营）

1. **定期反向图搜**：用商品主图 pHash 定期在搜索引擎图搜/电商平台检索，发现疑似克隆店铺。
2. **克隆店铺监测**：定期爬取关键词/品牌词搜索结果，比对页面结构与商品图指纹。
3. **DMCA 通道**：取证完备后向托管平台提交下架（Amazon Brand Registry / Shopify DMCA / 微信投诉等）。

## 5. 对标评审结论

**亮点**：
- 链路集中：上传与展示都走单一入口，保护逻辑可收敛在 `resources.py` + `minio_proxy.py` 两点，符合"复用优先、精简收口"。
- 复用已有能力：pillow 已在依赖中，sha256 已在资源表，无需引入重型新依赖。
- 分层设计对齐行业主线（访问控制 → 水印 → 取证 → 维权），与 Shopify 卖家/Cloudflare 官方实践一致。

**差距与修正**：
- 行业主流把签名 URL 放在 CDN 层（Cloudflare Images），Forge 目前网关无此类 CDN，改由 backend proxy 层实现，功能等价但会增加 backend 带宽压力（可接受，量级小）。
- 行业水印多为"导出前批处理"，Forge 改为"上传时自动处理"，覆盖更全、无需运营人工操作，优于行业基线。
- EXIF 元数据方案可靠性差（转发即丢），已降级为辅助项，不作为取证主链路。

**标准化评估**：
- pHash 字段、水印开关、签名密钥均需有明确配置项与文档承载；签名密钥走环境变量 + §13.4 红线，严禁入库。
- 新增 migration 按 §14.1 容器内执行、变更前备份。
