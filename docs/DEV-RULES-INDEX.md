# DEV-RULES 规则索引

> 本文档是 [DEV-RULES.md](./DEV-RULES.md) 的导航索引：按任务类型给出必读章节，并列出无条件全读的红线保底清单。
> 规则：**修改 DEV-RULES.md 时必须同步更新本文档**（见 DEV-RULES §7.5）；本文档本身被修改时同样要保证与 DEV-RULES 章节结构一致。

---

## 一、红线保底清单（无条件全读）

以下章节适用于**所有** Forge 开发任务，执行前必须完整阅读，不受任务类型影响，禁止以"任务简单"为由跳过：

| 章节 | 主题 | 必读理由 |
|------|------|----------|
| §1 | 版本管理 | 分支归集、命名、合并/CI 门禁；所有改动必须从 dev 切分支，禁止直改 dev |
| §3 | 部署策略 | 各端重建/部署规则（Admin 无 HMR 必须 `--no-cache`）、统一命令格式 |
| §9 | 会话启动上下文恢复 | 每次开工前必须实际检查 git 状态，禁止依赖对话摘要 |
| §12 | 临时文件与产物管理 | temp/ 目录纪律：测试产物入 temp/、交付物禁止入 temp/、清理触发条款 |
| §13 | 代码质量与安全检查 | 提交前质量门槛、安全红线（密钥/依赖审计/镜像漏洞） |
| §21 | 重建范围纪律与旧产物处置 | 禁止全量重建、必须核对 StartedAt、网关 access log 落盘 |

## 二、任务类型 → 适用章节映射

> 使用方式：红线保底清单（上表）**必读**；以下按任务类型追加必读章节。

| 任务类型 | 追加必读章节 | 说明 |
|----------|--------------|------|
| 后端 API / 服务代码修改 | §10、§11、§13.5、§14、§15 | 重建后必须端到端验证；提交前 hook 同参三连；涉 DB 走 migration 流程 |
| Admin 前端修改（admin/） | §2、§3.2、§8、§10、§11、§13.1、§18、§20、§22 | Admin 无 HMR 必须 `build --no-cache`；请求层/冻结/拖拽插槽专项规范 |
| portal-web 前端修改 | §2、§3.1、§8、§11、§13.1、§13.1.1 | 类型检查以容器内 vue-tsc 为准；HMR 覆盖范围判断 |
| 数据库变更 / migration | §14.1、§14.2、§15 | 容器内执行 alembic、变更前备份、失败回滚 |
| 容器重建 / 部署 / 环境操作 | §2、§3、§16、§21、§23 | 先查 INFRA-BASELINE；重建范围核对；访问统一走 127.0.0.1:8080；machine 存储排除系统盘、重建前备份 |
| 合并 dev / 发布 / 打 tag | §1.3、§1.4、§1.5、§1.6、§14.4、§15.1 | 先 CI 健康 → 用户验证通过 → 脚本合并；CI 查询优先 gh CLI；DoD 逐条满足 |
| Bug 排查 / 故障定位 | §8、§10、§11、§18、§20、§22 | 工作区神圣、先证明问题存在；冻结/自愈/插槽专项 |
| 方案设计 / 行业对标评审 | §19 | 方案必须先对标权威实践再定稿，输出对比表 |
| 文档 / 规则更新 | §6、§7、§17 | 禁止 AIGC 水印；**改规则必改本索引（§7.5）**；产出物 yyb-product 声明 |
| 会话启动 / 任务交接 | §9 | git 状态校验清单逐条执行 |
| 提交代码（通用） | §13.1、§15.2 | 质量门槛 + Conventional Commits |
