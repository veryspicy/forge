# 宠物用品 AI 独立站 — 管理后台需求规格

## 1. 概述

### 1.1 项目定位

宠物用品 AI 独立站是一个全球化宠物用品一件代发平台，面向中东、欧洲、北美等国际市场。平台不持有自有库存，所有商品来源于多家第三方供应商 API，用户通过 AI 聊天探针发现并购买商品。

### 1.2 后台目标

管理后台承载以下核心目标：

- **支撑多供应商 API 对接**：管理供应商接入、SKU 映射、价格同步
- **AI 探针商品推荐管理**：审核 AI 推荐记录、优化推荐策略
- **全款托管订单处理**：审核订单、推单采购、异常处理
- **定价引擎配置**：全局定价公式、区域差异化定价、促销活动
- **多角色协作**：管理员 / 运营 / 客服三级权限体系

### 1.3 与常规电商后台的差异

| 对比维度 | 常规电商 | 本平台 |
|---------|---------|--------|
| 库存管理 | 自有库存、出入库 | 无自有库存，依赖供应商 API |
| 商品来源 | 自建 SKU | 供应商 API 驱动、AI 探针入库 |
| 货架模式 | 有限货架，人工选品 | AI 无限货架，按需匹配 |
| 定价方式 | 手动标价 | 公式定价 + 区域差异化 + 促销叠加 |
| 订单处理 | 自有仓储发货 | 推送供应商采购、一件代发 |

## 2. 产品管理

### 2.1 产品入库三通道

| 通道 | 触发方 | 流程 | 适用场景 |
|------|--------|------|---------|
| AI 探针 | 用户聊天触发 | 用户提问 → AI 理解需求 → 调供应商 API 搜索 → 匹配商品 → 展示给用户 → 用户确认 → 自动创建商品 + 套公式定价 → 上架 | 用户找不到想要的商品时 |
| 手动上传 | 管理员/运营后台操作 | 填资料（多语言标题/描述/规格）+ 上传图片 → 选供应商/SKU → 设定售价（可覆盖公式）→ 上架 | 发现新品、供应商未接入 API、特殊商品 |
| API 自动同步 | 供应商系统推送 | 供应商商品变更自动入库 → 审核调价 → 上架 | 已接入 API 的供应商日常更新 |

#### 2.1.1 手动上传详细流程

1. 运营人员进入后台商品管理页，点击「新建商品」
2. 填写多语言信息（ar / de / en / fr）：
   - 商品标题
   - 商品描述
   - 规格参数（尺寸、重量、材质等）
3. 上传商品图片（多图，含主图和缩略图）
4. 选择供应商并绑定供应商侧 SKU ID
5. 系统自动套用定价公式计算建议零售价，运营可覆盖
6. 选择上架区域（可多选）
7. 保存为草稿或直接上架

#### 2.1.2 API 自动同步流程

1. 供应商系统推送商品变更（新增 / 修改 / 下架）
2. 后台自动入库，标记为「待审核」
3. 运营审核：检查多语言描述是否齐全、图片质量、售价合理性
4. 确认后上架，或驳回修改

### 2.2 AI 探针详细流程

```
用户在店铺 AI 聊天组件提问
  → AI 理解需求（宠物类型、品类、预算、区域）
  → 调用供应商 API 搜索匹配商品
  → 匹配成功：
      ├── 标品（低于阈值价）：自动创建商品 + 套公式显示零售价 → 用户确认 → 创建订单
      └── 高价/定制（高于阈值价）：展示估价 → 用户确认需求 → 运营审核报价 → 创建商品 → 创建订单
  → 匹配失败：告知用户暂无匹配，记录需求供后续选品参考
```

#### 2.2.1 探针配置

- **低价/高价阈值**：后台可配置，按品类或全局设置
- **推荐记录保留**：每次探针请求需保存以下信息：
  - 用户原始需求文本
  - AI 匹配到的商品列表（含匹配度评分）
  - 用户最终是否采纳（下单 / 忽略 / 拒绝）
  - 用于后续优化推荐模型

#### 2.2.2 探针记录查看

在后台 `/admin/chat-requests` 页面可查看所有 AI 探针推荐历史：

- 按时间范围筛选
- 按采纳状态筛选（已采纳 / 未采纳）
- 查看每次探针的完整对话链路
- 导出数据用于分析

### 2.3 商品结构

#### 2.3.1 多语言字段

商品核心信息需支持 4 种语言：

| 字段 | 语言 | 说明 |
|------|------|------|
| 标题 (name) | ar / de / en / fr | 各语言版本的商品名称 |
| 描述 (description) | ar / de / en / fr | 各语言版本的详细描述 |
| 规格参数 (specifications) | ar / de / en / fr | 尺寸、材质、重量等 |

#### 2.3.2 图片

- 支持多图上传
- 至少 1 张主图（primary）
- 缩略图自动生成
- 建议尺寸：主图 800×800、缩略图 200×200

#### 2.3.3 供应商关联

| 字段 | 类型 | 说明 |
|------|------|------|
| supplier_id | string | 供应商唯一标识 |
| supplier_sku | string | 供应商侧的 SKU ID |

#### 2.3.4 定价信息

| 字段 | 类型 | 说明 |
|------|------|------|
| cost_price | number | 成本价（供应商报价） |
| cost_currency | string | 成本价币种 |
| retail_price | object | 各区域建议零售价（自动计算 / 手动覆盖） |
| actual_price | number | 当前实际售价（叠加促销后） |

#### 2.3.5 商品状态

```
草稿(draft) → 已上架(active) → 已下架(inactive)
```

- **草稿**：商品已创建但未上架，仅后台可见
- **已上架**：前台可见可购买
- **已下架**：前台不可见，后台保留数据

## 3. 供应商管理

### 3.1 供应商档案

#### 3.1.1 基本信息

| 字段 | 说明 |
|------|------|
| 供应商名称 | 唯一标识 |
| 联系方式 | 联系人、电话、邮箱 |
| 发货地区 | 可多选，如 [中东, 欧洲] |
| 接入方式 | API / 手动 |
| 状态 | 合作中 / 暂停 / 已终止 |

#### 3.1.2 API 接入配置

| 配置项 | 说明 |
|------|------|
| 接口地址 (base_url) | 供应商 API 根路径 |
| 认证方式 | API Key / OAuth2 / Basic Auth |
| 认证凭据 | 加密存储的密钥 |
| 数据格式适配器 | 供应商数据格式 → 平台标准格式的转换器 |

#### 3.1.3 结算信息

| 字段 | 说明 |
|------|------|
| 成本价币种 | USD / EUR / AED 等 |
| 账期 | 月结 / 周结 / 单结 |
| 对账记录 | 历史对账明细 |

### 3.2 SKU 映射

每个上架商品需绑定一个供应商 SKU，映射关系如下：

```
平台商品 ID → 供应商 ID + 供应商侧 SKU ID
```

#### 3.2.1 映射管理

- 支持供应商侧 SKU ID 手动录入或 API 自动匹配
- 同一供应商 SKU 可映射到多个平台商品（不同区域的变体）

#### 3.2.2 SKU 变更通知

供应商侧发生以下变更时触发预警：

| 变更类型 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 价格变动 | 供应商调价 | 自动预警，运营确认后更新售价 |
| 库存变动 | 供应商缺货 / 补货 | 自动预警，影响前台库存展示 |
| SKU 下架 | 供应商停售 | 自动下架对应平台商品 |

### 3.3 供应商策略

- **长期方向**：只保留有 API 的供应商，实现自动化对接
- **过渡期**：手动供应商可继续使用，但不作为长期方案，新供应商必须提供 API
- **淘汰机制**：手动供应商逐步迁移至 API 或终止合作

## 4. 定价引擎

### 4.1 定价公式

全局默认公式：

```
售价 = 成本价 × 倍率(multiplier) + 固定运费(flat_shipping)
```

其中倍率和运费在后台可配置默认值：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| multiplier | 1.4 | 成本倍率 |
| flat_shipping | $5.00 | 固定运费 |

### 4.2 区域差异化定价

按目标市场设置独立的倍率和运费：

| 区域 | 倍率 | 固定运费 | 示例（成本 $20） |
|------|------|---------|-----------------|
| 中东 (AE/SA) | 1.5x | $5.00 | $35.00 |
| 欧洲 (DE/FR) | 1.3x | $8.00 | $34.00 |
| 北美 (US/CA) | 1.4x | $10.00 | $38.00 |

支持的配置维度：
- 按国家/地区设置
- 按币种自动换算
- 预留「区域组」概念，可多国家共用一套规则

### 4.3 单商品价格覆盖

每个商品可覆盖公式计算结果，手动设定售价：

- **全局覆盖**：为该商品设定固定售价，忽略公式
- **区域覆盖**：按区域单独设价，如中东 $35、欧洲 $30
- **覆盖优先级**：单商品覆盖 > 区域规则 > 全局公式

### 4.4 促销叠加

#### 4.4.1 促销类型

| 类型 | 配置 | 示例 |
|------|------|------|
| 满减活动 | 满 $X 减 $Y | 满 $50 减 $10 |
| 优惠券 | 固定金额 / 百分比折扣 | 减 $5 / 85 折 |
| 会员价 | 会员等级对应折扣 | VIP 享 9 折 |
| 限时折扣 | 指定时间段内打折 | 双十一 8 折 |

#### 4.4.2 叠加规则

定义促销间的叠加优先级和互斥关系：

| 规则 | 说明 |
|------|------|
| 优惠券与会员价互斥 | 默认不可叠加，取最优价 |
| 满减可与会员价叠加 | 先折后减 |
| 限时折扣与优惠券互斥 | 限时折扣优先 |
| 叠加顺序 | 会员价 → 满减 → 优惠券 |

叠加规则在后台可配置，支持自定义优先级。

## 5. 订单管理

### 5.1 支付模式：全款托管

```
用户下单 → 付全款（商品售价 + 运费）→ 平台托管
  → 订单进入「待处理」→ 运营审核/确认
  → 推送给供应商采购 → 供应商发货 → 物流追踪
  → 用户确认收货 → 货款结算给供应商 + 利润归平台
```

### 5.2 订单状态机

```
待支付(pending)
  → 已支付/待处理(paid)
    → 采购中(purchasing)
      → 已发货(shipped)
        → 运输中(in_transit)
          → 已送达(delivered)
            → 已完成(completed)
    → 采购异常(procurement_error)（供应商缺货/涨价）
      → 客服介入 → 已取消(cancelled) / 已退款(refunded)
```

### 5.3 订单列表

#### 5.3.1 筛选条件

| 筛选项 | 说明 |
|--------|------|
| 订单状态 | 多选 |
| 下单时间 | 日期范围 |
| 发货地区 | 目标国家/地区 |
| 供应商 | 按供应商筛选 |
| 订单编号 | 精确搜索 |

#### 5.3.2 列表展示字段

| 字段 | 说明 |
|------|------|
| 订单编号 | 唯一标识 |
| 用户信息 | 用户名、邮箱 |
| 商品信息 | 商品名 × 数量 |
| 金额 | 商品金额 + 运费 = 总金额 |
| 状态 | 当前订单状态 |
| 下单时间 | 时间戳 |
| 操作 | 查看详情 |

### 5.4 订单详情与操作

#### 5.4.1 订单详情页信息

- 用户信息（收货地址、联系方式）
- 商品明细（名称、SKU、数量、单价）
- 金额明细（商品小计 + 运费 + 税费 = 总计）
- 供应商信息（名称、SKU 编号、成本价）
- 利润预估（售价 - 成本价 - 运费）
- 支付信息（支付方式、支付时间、交易号）
- 物流信息（物流商、运单号、当前状态）
- 时间线（订单全生命周期时间轴）

#### 5.4.2 操作按钮

| 状态 | 可用操作 |
|------|---------|
| 待处理(paid) | **审核确认** / 取消订单 |
| 采购中(purchasing) | 查看采购进度 / 标记采购异常 |
| 已发货(shipped) | 更新物流单号 / 查看物流轨迹 |
| 运输中(in_transit) | 查看物流轨迹 |
| 采购异常(procurement_error) | 联系用户 / 退款 / 换供应商 |
| 已完成(completed) | 查看详情（只读） |

#### 5.4.3 采购异常处理

当供应商出现缺货、涨价等情况时：

1. 订单标记为「采购异常」
2. 运营人员在后台查看异常原因
3. 联系用户协商：
   - 换供应商（搜索替代 SKU）
   - 全额退款
   - 等待补货（设定等待期限）
4. 记录异常原因和处理结果，用于供应商评估

#### 5.4.4 退款处理

- **全额退款**：整单退款，退回用户支付的全部金额
- **部分退款**：单个商品退款，其他商品正常发货
- 退款后订单状态变更为「已退款」
- 退款原因需记录

## 6. 物流管理

### 6.1 物流追踪

- 对接国际物流查询 API（17TRACK / Aftership 等）
- 供应商发货后自动回传物流单号
- 买家端订单详情实时展示物流轨迹
- 后台支持手动输入物流单号补录

### 6.2 物流渠道

| 功能 | 说明 |
|------|------|
| 渠道推荐 | 按发货地区自动推荐物流渠道 |
| 渠道管理 | 后台维护可用物流商列表 |
| 手动选择 | 运营可手动选择/修改物流渠道 |
| 成本核算 | 物流成本计入订单成本，影响利润计算 |

### 6.3 物流异常

- 物流超时未更新 → 自动预警
- 包裹丢失/损坏 → 标记异常，客服介入
- 退回件处理 → 退款或重新发货

## 10. MCP 集成 — 大模型 Agent 对接

### 10.1 概述

后台作为 MCP (Model Context Protocol) Server，暴露店铺管理能力给外部大模型 Agent（如 Claude Desktop、Cursor、自定义 Agent 等）。大模型可通过 MCP 协议调用后台 API，实现 AI 驱动的选品上架、数据同步、店铺运营。

### 10.2 典型场景

| 场景 | 大模型角色 | 操作 |
|------|-----------|------|
| 热销品榜单选品 | 大模型搜索 TikTok/eBay/亚马逊热销榜 → 筛选适合宠物用品的商品 | 调用 MCP Tool 批量创建商品到店铺草稿箱 |
| 出口数据分析选品 | 大模型分析海关出口数据 / Google Trends → 发现区域爆品 | 调用 MCP Tool 创建商品并关联供应商 |
| AI 自动定价 | 大模型分析竞品价格 → 给出定价建议 | 调用 MCP Tool 批量更新商品售价 |
| 库存预警处理 | 大模型监控供应商库存变动 | 调用 MCP Tool 自动下架缺货商品 |
| 内容生成 | 大模型生成多语言商品描述 | 调用 MCP Tool 更新商品多语言字段 |

### 10.3 MCP Server 架构

```
外部大模型 Agent (MCP Client)
  │
  │  MCP 协议 (stdio / SSE)
  │
  ▼
后台 MCP Server (/mcp 端点)
  │
  ├── Tools: create_product / update_product / list_products / update_stock / ...
  ├── Resources: product://{id} / supplier://{id} / order://{id}
  └── 鉴权: API Key 验证
  │
  ▼
现有后端 API 层 (forge.api.v1)
```

### 10.4 暴露的 MCP Tools

| Tool 名称 | 功能 | 参数 |
|-----------|------|------|
| `create_product` | 创建商品（草稿） | 多语言标题/描述、品类、供应商ID、成本价、图片URL、规格 |
| `update_product` | 更新商品信息 | product_id + 任意可更新字段 |
| `list_products` | 查询商品列表 | 筛选条件（品类/状态/供应商）、分页 |
| `update_product_price` | 更新商品定价 | product_id、各区域售价 |
| `set_product_status` | 商品上下架 | product_id、状态（draft/active/inactive） |
| `list_suppliers` | 查询供应商列表 | 筛选条件 |
| `get_supplier_products` | 查询某供应商的商品 | supplier_id |
| `batch_create_products` | 批量创建商品 | 商品数组（最多50个） |
| `get_sales_stats` | 获取销售统计 | 时间范围、品类筛选 |

### 10.5 MCP Server 实现方案

- 使用 Python MCP SDK（`mcp` 包）
- 作为 FastAPI 子应用挂载到现有后端，路由 `/mcp`
- 支持 SSE 传输（便于远程 Agent 连接）
- API Key 鉴权：每个大模型 Agent 分配独立 API Key，可限制权限范围
- 操作审计日志：记录每个 MCP Tool 调用（Agent 标识、操作、参数、结果）

### 10.6 安全约束

- MCP Tools 的操作权限受角色限制（如只读 Agent 只能调用查询类 Tool）
- 批量操作上限限制（单次最多 50 个商品）
- 创建的商品默认为「草稿」状态，需人工审核后上架（可配置为自动上架）
- API Key 可随时吊销

## 11. 资源管理（Resource Management）

> 2026-08-16 头脑风暴定稿。目标：资源管理成为**全站唯一上传入口**，所有业务表单只做引用。

### 11.1 定位与原则

- 全站所有文件上传（品牌 logo、轮播图、商品图、文章图等）统一经资源管理录入 MinIO 并登记到 `resource` 表
- 业务表单不再直接持有 URL，改为引用 `resource.id`
- 分两阶段落地（见 11.6）

### 11.2 页面结构（一级菜单，三区域布局，对齐站点配置）

| 区域 | 内容 |
|------|------|
| 左 | 资源类型列表：全部 / 图片 / 视频 / 音频 / 文档，带各类型数量角标 |
| 中 | 资源列表（缩略图网格，默认上传时间倒序）+ 顶部工具栏：上传按钮、搜索框、批量删除 |
| 右 | 选中资源详情：大图预览 / 播放器、名称（可重命名）、类型、大小、上传时间、MinIO 路径、URL 复制、下载、引用位置、删除 |

### 11.3 数据模型

```sql
resource (
  id            uuid PK
  site_id       uuid            -- 站点隔离
  bucket        varchar         -- minio 桶
  object_key    varchar         -- minio 对象路径
  url           varchar         -- 访问 URL
  file_type     varchar         -- image/video/audio/document
  mime          varchar
  file_size     bigint
  sha256        varchar         -- 去重
  name          varchar         -- 可重命名
  created_by    uuid
  created_at    timestamptz
  deleted_at    timestamptz NULL -- 软删，回收站式
)

resource_ref (  -- 引用关系表，用于"引用位置"追踪
  resource_id   uuid
  ref_type      varchar         -- brand_logo / product_image / ...
  ref_id        varchar         -- 业务对象 id
  ref_label     varchar         -- 展示文案（"品牌 logo"、"商品 A 主图"）
)
```

### 11.4 接口设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/admin/v1/resources/upload | 上传（multipart），写入 MinIO + 登记 resource |
| GET | /api/admin/v1/resources | 列表，支持 type/site_id/keyword/page |
| GET | /api/admin/v1/resources/{id} | 详情（含引用位置） |
| PATCH | /api/admin/v1/resources/{id} | 重命名 |
| DELETE | /api/admin/v1/resources/{id} | 软删（有引用时禁止） |
| DELETE | /api/admin/v1/resources | 批量软删 |

### 11.5 关键约束

1. 删除走软删（deleted_at），不物理删 MinIO 对象，可恢复
2. 有 resource_ref 引用的资源禁止删除，右侧提示引用位置
3. 站点隔离：admin 只看本站资源，super_admin 可切"全部"
4. 文件限制：图片 10MB / 其他 50MB；类型白名单，SVG 消毒复用现有逻辑
5. 上传命名：object_key = `site/{site_id}/resources/{uuid}.{ext}`
6. 权限：查看/上传 admin、operator 均可；删除仅 super_admin、admin

### 11.6 分阶段落地

| 阶段 | 内容 |
|------|------|
| 第一版 | 资源管理页面 + resource 表 + 上传/列表/详情/删除接口；**各表单上传链路不动**，只把新上传统一登记进 resource 表 |
| 第二版 | 品牌配置、商品等表单的"上传"改为"上传新资源 或 从资源库选择"弹窗（复用资源管理组件）；弹窗内保留上传能力 |

### 11.7 存量数据现状（2026-08-16 核查）

- products 表当前**无图片字段**（ORMProduct 无 image 列）
- 现有图片全部以 URL 字符串存于 `site_profiles.config`（JSONB）：brand.logo.data、carousel.images 等
- 上传接口仅 `POST /api/admin/v1/site/upload-image`，直接返回 URL，无资源登记表
- 结论：`resource_ref` 迁移工作量小，第一版只需扫描 site_profiles.config 中的 URL 字段
